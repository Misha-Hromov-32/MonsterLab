# Безопасность

## Как сообщить об уязвимости

Пожалуйста, не сообщайте об уязвимостях в открытых issue. Напишите закрыто через
[Security Advisories](https://github.com/Misha-Hromov-32/MonsterLab/security/advisories/new) — ответим в течение недели.

## Что уже сделано

- Админ-панель: пароль (из `ADMIN_PASSWORD` или сгенерированный, файл с правами `0600`), подписанные
  HMAC-токены на 7 дней; смена `ADMIN_PASSWORD` (после перезапуска) отзывает все выданные токены.
  Перебор пароля ограничен: 5 попыток за 5 минут с одного адреса.
- Лимиты считаются по адресу клиента. `X-Real-IP` бэкенд принимает только от своего nginx
  (`TRUST_PROXY=1` в `docker-compose.yml`), а nginx верит `X-Forwarded-For` только от адресов
  из `REAL_IP_FROM` (внешний HTTPS-прокси) — иначе заголовок подставил бы кто угодно.
- Ответы API не раскрывают внутренностей: необработанные ошибки и сбои моделей возвращают общую
  фразу, подробности — только в журнале сервера.
- Ключ ProxyAPI хранится только на сервере, в интерфейс передаются лишь последние 4 символа ключа.
  Адрес API принимается только `https://`.
- Загрузки: не больше 25 МБ на файл, 40 мегапикселей на картинку и сторон 1 : 8, число файлов ограничено,
  файлы примеров отдаются только по проверенным id — выйти за пределы папки нельзя.
- Экспертный разбор тратит деньги с баланса ProxyAPI, поэтому ограничен: 10 запросов за 10 минут
  с одного адреса. Анализ — 60 запросов в минуту.
- Контейнер бэкенда работает от непривилегированного пользователя и наружу не публикуется —
  только через nginx.

## Рекомендации для своего сервера

- Задайте `ADMIN_PASSWORD` в `.env` и откройте сайт через HTTPS (пример с Caddy — в
  [docs/deploy.md](docs/deploy.md)).
- Если сервис открыт в интернет, а экспертный разбор включён, следите за балансом ProxyAPI.
